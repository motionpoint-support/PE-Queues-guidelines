PE queues: cheat sheet

PE - Misalignments

Send here

  • A visual element on the page is misaligned compared to the origin
  • Visual element revisions to the page (using CSS)

Not here: text inside an image (TAM), broken image or link (Functionality), untranslated text (Translation), same issue on origin (customer's side)

Document before you assign

  • URL and language
  • Screenshots of the origin AND the translated page
  • Browser and screen width
  • Where on the page it happens
  • Screenshots: "See screenshot(s) below" (in the Post) or "Screenshots are attached" (in Files)

PE - Translation

Send here

  • Appendix A or Scoping & Quoting: Rule A/B/C/D scope of work revisions (changing the scope, or quoting the cost to change a rule)
  • WebCATT project/page translation queue revisions
  • Text and image activations
  • Content that needs PE assistance to enter the translation queue
  • Content that has been translated but is not showing translated on the page
  • Translated content with unexpected encoding or Directive Tags showing on screen
  • Content optimizations (DTs, merges, breaks, blocks)
  • WebCATT content issues (encoding, code in queue, unwanted pages, N/A results)
  • Broken or bad checksum images encountered in the file translation queue
  • Machine translation issues

Document before you assign

  • URL, language, and the exact text (copied)
  • PID / SID, or the WebCATT project and filter
  • What you tried: push (mpactionid/Charles), TM Search, cache, incognito
  • Scope change: the rule, the path, and what should change
  • Screenshots: "See screenshot(s) below" (in the Post) or "Screenshots are attached" (in Files)

PE - Functionality

Send here

  • Active disruptions to uptime and availability (validated site outage, latency)
  • Unexpected or unwanted behavior: URL redirects, wrong redirects on links or images
  • Functional concern with a webpage, web service, or API
  • Missing website content
  • Broken images on the website
  • Website navigation / hyperlink concerns
  • Customization (content, headers)
  • EasyLink
  • Language toggle
  • Speedbump / splash page
  • Global Site Map (GSM)
  • On Site Search (OSS)

Document before you assign

  • URL and language
  • Steps to reproduce, expected vs actual
  • Origin test result
  • Browser and device
  • Screenshots ("See screenshot(s) below" or "Screenshots are attached") or video
  • Can't replicate? A HAR file
  • Outage: when it started, what is down, how widespread

PE - Other

Send here

  • Non-active site outage, or uptime and availability concerns
  • Root cause analysis
  • Customer call requests
  • General platform and technology questions
  • Quotes / time estimates
  • IP whitelist clarification
  • WebCATT inaccessible / TServer properties not found
  • Requests to block user-agent strings or IP addresses

Document before you assign

  • RCA: dates, times, time zone, what happened, related cases
  • Call: purpose, who joins (roles), 2-3 time slots with time zone
  • Quote: exactly what they want, and by when
  • IP whitelist: what they block, where they are hosted, the list sent
  • WebCATT access: user and the exact error (see screenshot below)
  • Blocking: the exact user-agent strings or IPs, and why

Common questions

Are these all of our known IP addresses?
No. The page lists the public-facing, outbound IP ranges customers need to allow so our technology and staff can reach their origin unimpeded.
What does "outbound" mean?
Unlike most home internet setups, the IPs used to reach our platform are often different from the IPs that make requests to the origin.
Why doesn't the page have every IP we control?
Customers never need them all. Some inbound ranges, load balancers, and MotionCore systems used for internal routing are left out.
Should I send everything on the page?
Yes. On the first attempt, send all of them.
Can I include the headings, remarks and labels?
Only the three major column headings. No additional details.
The customer says the list is too long. How do I reduce it?
1) Remove ranges for data centers they are not hosted in, and keep the rest intact. 2) If they keep pushing back, reduce the hosting ranges to their specific machine(s) + the WebCATT machine, and make sure they know hosting can change without notice (the full ranges cover that).
What are the IPs with a slash?
IP ranges in CIDR (Classless Inter-Domain Routing) format. A CIDR tool makes them easier to read and explain.

CIDR tool: ipaddressguide.com/cidr
